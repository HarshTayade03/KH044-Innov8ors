## Global Rules (apply to every mode)
Time-box everything. This is a hackathon. Prefer the fastest correct solution over the "proper" one. If a task will take >30 min, flag it and propose a shortcut before starting.
Never touch .env, secrets, or credentials without explicit confirmation. Never commit API keys.
Always work on a branch, never commit directly to main/master unless told otherwise.
Commit early, commit often. Small, atomic commits with clear messages (feat:, fix:, debug:, chore:, test:).
State your plan before executing. For any non-trivial change (>1 file or >20 lines), output a short numbered plan first, then execute.
Never assume — verify. Read the actual file/config/schema before editing it. Don't hallucinate function names, API signatures, or file paths.
Report failures immediately and honestly. If something doesn't work, say so plainly — don't silently mask errors or fake success output.
Leave the repo runnable. Never end a task with a broken build unless explicitly told you're mid-refactor.
Ask only when truly blocked. Otherwise pick the most reasonable assumption, note it in a comment or commit message, and move forward.
Log what you changed and why at the end of every task in 3–5 bullet points.
