01 · OVERVIEW

What this product is

The AI-Assisted Vulnerability Triage Platform is a local-first workspace for turning heterogeneous security reports into reviewable vulnerability cases. It reduces duplicate investigation and exposes the reasoning behind prioritization; it does not silently declare a target exploitable.

Product ruleReported, inferred, simulated, and validated information are kept distinct throughout the workflow.

02 · DETECTION WORKFLOW

What a security officer can do

  1. ImportUpload JSON or SARIF exports, or add a manual finding. The parser records source scanner, batch identity, quality, and original evidence.
  2. Extract viewsGenerate description, location, reproduction, and impact views. Derived text is redacted before display and embedding.
  3. Generate representationsCreate provenance-labeled embeddings for similarity analysis. The local hashing fallback is disclosed when a learned model is unavailable.
  4. DeduplicateRun fingerprint and guarded semantic clustering. Asset, host, package, and parameter incompatibilities block unsafe merges.
  5. PrioritizeCalculate a deterministic score with visible contributions from severity, exploit probability, exposure, asset context, and validation state.
  6. Validate selectivelyRequest an offline SQLi, XSS, or SSRF lab scenario for an issue. The result is simulated evidence, never proof of real exploitability.
  7. ReviewAssemble cases, request more evidence, approve or reject with a reason, and inspect the audit history.

03 · EVIDENCE

What is retained

Original scanner evidence is preserved separately from derived views and artifacts. Derived validation artifacts are redacted, size-checked, and stored with SHA-256 hashes. Retrieval verifies the hash before serving content.

SourceImmutable scanner payload and provenance

DecisionRisk contributions, review reason, actor, and audit event

04 · GOVERNANCE

Human review is the control point

Automation prepares evidence and recommendations. Only an analyst action can approve or reject a case. Review transitions, overrides, evidence requests, and stale-case changes are persisted with actor and reason.

05 · CURRENT BOUNDARIES

What is deliberately not claimed

  • Offline validation is a controlled simulator; real Docker execution is disabled.
  • Threat intelligence defaults to local mock feeds; live refresh is explicitly unsupported.
  • Embeddings and semantic clustering are analysis aids, not proof of equivalence.
  • Scanner reports and CWE labels do not automatically confirm exploitability.
  • Slack, Jira, webhooks, and scanner polling are not implemented integrations.
